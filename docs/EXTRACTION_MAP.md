# Extraction map — private proven code → public Forge engine

This is the inventory for Plan 1: exactly which functions/classes to lift from the proven
private repos into `forge/`, what their public signature becomes, and what must be
genericised before the code can live in an MIT public repo. Every row below was produced by
reading the real private source — no signature here is invented.

**Secret-scrub rule (MANDATORY):** nothing lifted may carry LAN IPs, access codes, serials,
check codes, Mongo URIs, or private Drive/filesystem paths. Those become constructor/config
parameters with **no hardcoded default**. Any example value shown below is written as
`REDACTED` — this document records *where* a secret is used and that it becomes a parameter,
never the value itself. (Self-check performed before commit: grepped this file for IPv4
patterns, `AD5X_`/`BAMBU_` secret values, and `.relayforge_secrets` contents — none present.)

## Extraction status summary

- **Clean lift, already genericised:** `classifier.py`, `reader.py`, `jobqueue.py`,
  `dispatcher.py`, `adapters/base.py` (Protocol as far as it goes), `AD5XAdapter.status/send`,
  `DriveInbox`. These carry no secrets and their constructors already take config as
  parameters.
- **Lift + must strip a secret-loading default:** `adapters/ad5x.py`'s
  `secrets_path="~/.relayforge_secrets"` convenience, and `adapters/bambu.py`'s
  hardcoded `BAMBU_IP` fallback default — both must become required, default-less
  constructor args in the public engine.
- **Lift + design gap:** `watch()`/`stop()` on the `Adapter` Protocol — informally proven
  (AD5X `cmd_watch`/`cmd_stop`, Bambu `pause/resume/cancel`) but never formalized as a
  contract method. Mark **TODO-verify** in Plan 1.
- **Nothing to lift — write fresh:** `adapters/klipper.py`. No Moonraker/Klipper adapter
  code exists in any private source read for this task; only a hands-on runbook
  (`docs/PRINT_FLOW.md`, already public in this repo) describes the intended calls. Plan 1
  must design this adapter and its Moonraker `firmware_restart` retry policy from scratch.
