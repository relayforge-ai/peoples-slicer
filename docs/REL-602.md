## Today's A1 mini miss (2026-09-01)

Jules fill job `fill-20260901-a1mini-flexypup`, SKU
`pv-flexy-pup-magnet-and-keychain-magnet`. Exact Dawes 11:42 PT error:

```
SliceError: REL-602 output validation failed: multicolor slice requires
enable_prime_tower = 1 on every printer — refusing artifact and requesting
a corrected/manual slice
```

Slicer was BambuStudio AppImage v02.07.01.62 via `multi_slicer.slice_for`
(`backend=bambu`, `a1mini`) — not Orca, not People's Slicer yet.

**Verified on disk:** the source is a Printverse **Kobra Max** project, 5
colours (`#80FF80;#FFFFFF;#0000FF;#6F5034;#FFFF00`), `printable_area` 400 mm,
`enable_prime_tower=0`. `--load-settings` rewrote `printer_model` →
`Bambu Lab A1 mini` and `print_settings_id` → `0.20mm Standard @BBL A1M`,
but **left `enable_prime_tower=0` and leaked `wipe_tower_y=220` onto the
180 mm bed**. The A1 mini vendor flatten already had `enable_prime_tower=1`;
the 3mf overrode it.

People's Slicer now sanitizes the maker 3mf (and restamps the flattened
process) so those keys cannot win: tower on when `colors>1`, bed + wipe
tower from the target printer. REL-602 artifact validation is unchanged
and still refuses a leaked file.

It is also a **two-plate magnet** 3mf (captured + glue-in). Default remains
glue-in / non-captured only.

**Tests that catch this file class:**
- `tests/test_retarget_kobra.py::test_five_color_kobra_retargeted_to_a1mini_stamps_process`
- `tests/test_magnet_plates.py::test_two_plate_magnet_project_slices_glue_in_only`

## Multi-part plates

`slice_for(..., extra_models=...)` and `build_backend_cmd` accept multiple
model paths. Until explicit placement exists, `cap_same_plate_models` keeps
at most two parts of similar height (the 44/26/18 mm spaghetti plate).
Magnet captured + glue-in is **not** this path.
