# REL-602 — tests that catch what the printer caught

## Today's A1 mini miss (2026-09-01)

Jules fill job `fill-20260901-a1mini-flexypup`, SKU
`pv-flexy-pup-magnet-and-keychain-magnet`. Operator: slice failed, tagged
REL-602, "prime tower off"; no send. AMS empty / Sample PLA on the bed did
not matter — the slice died first.

**What the code actually does (not the prime-tower hypothesis):**

Prime tower is a *send* gate (`guardian.py`: multicolor requires
`enable_prime_tower = 1`). A failed slice never reaches it. The SKU is a
**two-plate magnet 3mf** (captured / print-in-place + glue-in / non-captured).
`build_backend_cmd` used to hardcode `--slice 1` and a single model path, so
Jules sliced the captured plate — or could not execute the plate the policy
had planned.

Telchar default (Ryan, same day): **glue-in / non-captured only**. Do not
arrange captured + glue-in as a multi-part plate.

**The test that would have caught it:**
`tests/test_magnet_plates.py::test_two_plate_magnet_project_slices_glue_in_only`

That test builds the same two-plate shape, dry-runs `slice_for`, and requires
`--slice 2` plus a single trailing model path.

Catalog pairs (`pv-mini-cow-magnet-captive` vs
`pv-mini-cow-magnet-non-captive`) prefer non-captive via
`prefer_non_captive_path`.

## Real slice per printer

`test_real_slice_artifact_printer_model_and_bed` (marked `@pytest.mark.slow`)
runs one live slice per `a1mini` / `a2l` / `ad5x` / `ender` when the AppImage
and `xvfb-run` are present, then calls `assert_sliced_artifact`. CI without
binaries skips — the test still exists.

## Multi-part plates

`slice_for(..., extra_models=...)` and `build_backend_cmd` accept multiple
model paths. Until explicit placement exists, `cap_same_plate_models` keeps
at most two parts of similar height (the 44/26/18 mm spaghetti plate).
Magnet captured + glue-in is **not** this path.
